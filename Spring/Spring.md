## 🔍 핵심 컴포넌트별 역할 정리 (비유와 매칭)

| 역할 (컴포넌트) | 비유 | 주요 어노테이션 / 개념 | 설명 |
| :--- | :--- | :--- | :--- |
| **1. Controller** | 접수원 👧 | `@Controller` | 사용자의 요청을 가장 먼저 받고, Service에 일을 전달함 |
| **2. Service** | 현자 🧙‍♂️ | `@Service` | 핵심 비즈니스 로직을 생각하고 처리 방침을 지시함 |
| **3. DAO** | 비서 🧑‍💻 | `@Repository` (또는 `@Mapper`) | 데이터에 접근하기 위해 MyBatis(사신)에게 부탁함 |
| **4. Mapper (XML)** | 데스노트 📓 | SQL 쿼리문 | 어떤 SQL을 실행해야 할지 적혀 있는 주문서 역할 |
| **5. MyBatis** | 사신 💀 | SQL 실행 도구 | 데스노트(XML)를 읽고 DB에 명령을 내림 |
| **6. DB** | 용 🐉 | MySQL 등 | 실제 데이터를 저장하고 있고, 요청에 맞는 데이터를 찾아 돌려줌 |
| **7. VO** | 보물상자 📦 | `UserVO` 등 | 데이터를 안전하게 담아서 전달하는 객체 |

## 💡 추가 핵심 개념

- **인터페이스(계약서) vs 구현체(실제 구현):**
  - `UserDao`(인터페이스)는 "이런 기능이 있다"고 약속만 해두고, `UserDaoImpl`(구현체)이 실제로 어떻게 수행할지 정의함. (느슨한 결합을 위한 구조)
- **Spring Container와 Bean:**
  - 스프링 마을(컨테이너)은 모든 Bean(객체들)을 관리하고 서로 연결해 주는 마법 학교 같은 역할.
- **`@Autowired` (소환 마법):**
  - 필요한 Bean을 수동으로 일일이 찾지 않고, 스프링이 자동으로 쏙 찾아와서 연결해 주는 마법!
